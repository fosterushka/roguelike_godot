# Архив проверок и старые отчёты

Актуальные механики описаны в [PROJECT.md](PROJECT.md), повторяемые процедуры в [testing.md](testing.md). Этот файл объясняет статус всех сохранённых артефактов; он не переоценивает старые результаты как новые.

## Что хранится

| Путь | Статус и назначение |
| --- | --- |
| `docs/validation/` | Локальные JSON-отчёты, engine/stdout-логи, PNG, импорты и заметки отдельных проходов. Весь каталог исключён из Git текущим .gitignore. В чистом checkout его может не быть. |
| [PERFORMANCE_REPORT.md](PERFORMANCE_REPORT.md) | Исторический статический benchmark пространственных MultiMesh и terrain; границы измерения сохранены внутри. |
| [performance-measurements.json](performance-measurements.json) | Исходные численные данные этого benchmark. Не текущий результат и не конфигурация игры. |
| [model-revision-report.html](model-revision-report.html) | Историческое сравнение моделей до/после; изображения находятся в локальном validation. Старые деревья и дальний вариант ели уже заменены. |
| `assets/models/**/stats.json`, `assets/models/validation.json` | Статистика конкретного экспорта моделей. Не число активных объектов рейда и не подтверждение текущего рендера. |

JSON, PNG и логи сохранены без подмены результатов. Старые заметки внутри validation помечены как исторические. В них могут быть прежние названия UI, команды, число тестов и уже удалённые модели; это хронология, а не инструкция повторно внедрить их.

## Как читать доказательства

Сначала найдите команду, ревизию, список сценариев и окружение. Если ревизия или лог отсутствуют, не считайте результат подтверждённым для нынешнего дерева. Объединение полного прогона с отдельными повторениями не является новым единым полным прогоном. Успех при старом manifest не покрывает добавленные позднее тесты.

Кадр доказывает только показанную сцену. Старый счётчик треугольников, 221 экспонат или исправление дальнего дерева не является требованием к нынешним ассетам. Отсутствующая локальная картинка означает недоступный артефакт, а не отсутствующую игровую модель.

Для нового отчёта укажите дату, commit/локальные изменения, точную команду, движок и renderer, профиль/seed, список проверок, результат и ограничения. Для замера FPS добавьте устройство, размер окна, кеш, VSync/лимит и длительность. Итог должен следовать из report.json и логов, а не из вручную написанного количества PASS.
