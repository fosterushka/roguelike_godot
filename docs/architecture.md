# Архитектура проекта

Сверено с рабочим деревом 2026-09-06. Это текущая одиночная Godot-игра; сервер, PvP и сетевые игроки в её состав не входят. Старые планы переноса и инструкции копирования из временных каталогов больше не являются рабочим процессом.

## Ответственность модулей

| Каталог | Назначение |
| --- | --- |
| [app](../app) | Сборка сцены, маршрутизация экранов и ввода; отдельные потоки каравана и открытия кейсов |
| [modules/session](../modules/session) | Часы рейда, состояния запуска/паузы/результата, границы симуляции |
| [modules/caravan](../modules/caravan) | Движение, состояние прицепов, сцепка, оборудование, сохранение состава |
| [modules/combat](../modules/combat) | Урон, цели, снаряды, враги, волны и боевые эффекты состояния |
| [modules/crew](../modules/crew) | Роли, зарплата, посадка, сбор и доставка груза |
| [modules/meta](../modules/meta) | Убежище, инвентарь, торговля, миссии и результат экспедиции |
| [modules/progression](../modules/progression) | Покупки модулей, уровни, протоколы и профиль |
| [modules/world](../modules/world) | Генерация, столкновения, разрушение, погода, активности и эвакуация |
| [presentation](../presentation) | Модели, анимация, камера, звук, HUD и остальные экраны |
| [infrastructure](../infrastructure) | Подготовка ресурсов и запись профиля |

[app/main.gd](../app/main.gd) соединяет эти части. Изменения правил следует делать в соответствующем модуле; UI передаёт команды и показывает состояние.

## Данные и ресурсы

- [data/game_catalogs.json](../data/game_catalogs.json) содержит каталог, первоначально экспортированный из TypeScript. Он не заменяет исполняемые правила GDScript.
- [scripts/export_game_catalogs.mjs](../scripts/export_game_catalogs.mjs) обновляет каталог из внешнего исходного проекта. Скрипту нужны Node.js и `esbuild` в исходном проекте; самой игре они не нужны. Локальные дополнения берутся из [godot_module_additions.json](../scripts/godot_module_additions.json).
- [data/missions.json](../data/missions.json) задаёт миссии; справочник [missions.md](missions.md) отражает этот файл.
- [data/asset_manifest.json](../data/asset_manifest.json) перечисляет ресурсы подготовки. Импорт файла, создание модели и готовность GPU являются разными стадиями.
- Текущий игрок использует [military_pickup.glb](../assets/vehicles/military_pickup.glb), подключённый через [military_pickup.gd](../presentation/vehicles/military_pickup.gd). Модели исходного переноса также остаются для остальных объектов и отдельных совместимых путей; см. [представление](presentation-parity.md).

## Состояние и сохранения

По умолчанию профиль записывается в `user://iron_caravan_profile.json`, язык в `user://iron_caravan_language.cfg`. Тестовые сцены задают отдельные пути. Операции убежища учитывают результат записи и откатывают неподтверждённые изменения; подробности в [expedition-gameplay.md](expedition-gameplay.md).

У рейда, аккаунта и визуального представления разные жизненные циклы. Статистика и постоянный склад переживают запуск, временный груз обрабатывается результатом рейда. [Боевой контракт](../modules/session/combat_contract.md) описывает границы систем.

## Границы подтверждения

Наличие реализации и тестов не доказывает полное совпадение с исходным TypeScript-проектом, отсутствие задержек GPU или комфорт баланса. Текущие правила описаны тематическими справочниками, а сохранённые доказательства и открытые проверки перечислены в [testing.md](testing.md).
