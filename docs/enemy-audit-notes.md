# Все противники и места появления

Проверен текущий runtime Godot в staging. Это обзор кода, а не доказательство ручного прохождения. После аудита отдельным проходом добавлены недостающие названия шести типов в EN/RU; игровые правила не менялись.

## Не отдельные типы врагов

- Части Левиафана имеют `type=bossComponent`: `missilePod` (220 HP, ракеты 34), `gunPod` (190 HP, пули 13), `leftDrive`/`rightDrive` (по250 HP), `core` (360 HP, круговой залп из8 ракет и при захвате цели дополнительный веер из5). Первые две части доступны в фазе0, приводы в фазе1, ядро в фазе2. Источник: `leviathan_rules.gd:7,59,88`.
- Охрана заводов: существующие `rifleman`/`ak`, всего до2+tier около каждого завода. Задание помощи поселению создаёт трёх `rifleman`. Конвой использует `buggy`+`bike`. У этих экземпляров `counts_toward_wave=false`, это варианты происхождения, а не новые типы.
- `scavengerRoute` является нейтральной активностью, не создаёт враждебный `kind`.
- Мины создаются отдельно через `mine_rules.gd:15`: урон30, радиус2.35, вооружение0.9с, жизнь25с, до6 на владельца/36 всего; могут перейти на сторону игрока после взлома. Это опасные объекты, не враги фабрики.
- Молнии, торнадо, грязь, граница мира и снаряды также не являются типами врагов.
- `drone`, `raider`, `boss` — имена визуальных моделей. Визуальный alias `fortress` поддержан рендерером, но отсутствует среди разрешённых `spawn_enemy(kind)`.

## Границы фабрики и замечания

1. Фабрика отвечает за проверку `kind`, копирование определения, базовое состояние экземпляра и специальные инициализаторы. Расписание волн, поиск безопасной позиции, лимиты количества и добавление в живой мир остаются в runtime/spawn rules.
2. Сохранять последовательность RNG: общий случайный cooldown, затем два значения для дрона, отдельная скорость bike/buggy. ID выделяется только после успешной проверки лимитов. Босс дополнительно выделяет5 ID частей через `Leviathan.setup`.
3. Добавление обычного варианта существующего поведения должно требовать определения, visual ID и названий. Новое поведение требует отдельного обработчика. Сейчас `enemy_ai.gd` использует точные `kind` для bomber/kamikaze/repairCrawler/minelayer: одного копирования полей `detonate` недостаточно.
4. Связь с визуальным пулом задаёт поле `model` каталога; список пулов и слоты пехоты строятся по каталогу. Factory-тест проверяет модель и её предварительную загрузку. Соответствия: shooter→drone, keep→raider, leviathan→boss.
5. По отдельному запросу включены jammerTruck с волны2 и repairCrawler/minelayer с волны3, по одному каждого типа в последующих волнах. Неактивным остаётся только обычный keep; босс leviathan доступен в волне6.
6. Данные ремонтника расходятся: JSON содержит supportRange64, живой `Priority.valid_repair` ограничивает36. Таблица выше описывает runtime. Названия bike, buggy, keep и трёх garrison добавлены в локализацию после аудита; показ в настоящем HUD проверяется для обоих языков в ui_menu_regression_test.gd.
