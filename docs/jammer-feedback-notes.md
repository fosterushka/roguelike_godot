# Jammer proximity feedback

The visuals consume the gameplay snapshot fields `jammed`, `jammer_strength`, `jammer_reversed`, `jammer_pulse`, `jammer_source_id`, `jammer_source_position` and `jammer_radius`. They do not calculate an independent jammer radius or change input. Three thin waves expand above the selected hostile transmitter, while six small interference sparks orbit near the player's roof. Wave radius is a compact visual fraction of the gameplay radius, not a collision boundary. Strength controls opacity and the actual reversal pulse changes the color.

All nine gameplay meshes and materials, plus two dedicated warmup previews, are created on readiness and reused. Rings use TorusMesh geometry and sparks use BoxMesh; no new texture or shader assets are needed. Alpha never exceeds 0.48. Normal depth testing, disabled transparent depth writing and render priority 0 keep the airborne effect compatible with actor depth and existing ground decal priorities. There is no ground field plane or fullscreen interference layer.

The upper-left HUD shows a small signal meter and localized `SIGNAL JAMMED` label. `CONTROLS REVERSED` appears only while the gameplay field says input is actually reversed. Both labels switch immediately between English and Russian. The control and its labels ignore mouse input; the gameplay HUD parent hides it in menus and pause. The world effect follows the cinematic clock, so a paused scene and zero simulation delta freeze its animation. Run reset clears retained state. Leaving the true gameplay radius removes the reversal label immediately and uses the gameplay strength decay to fade the remaining visual signal.

Tests use actual jammer rules for in-range pulse and out-of-range fade, and cover material depth/opacity, bounded mesh counts, warmup inertness, real SceneTree pause, death/reset cleanup, menu visibility and both languages. No graphical rendering, GPU timing or subjective appearance validation was performed.
