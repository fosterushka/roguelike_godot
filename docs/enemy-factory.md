# Добавление врага

`modules/combat/enemy_catalog.gd` содержит16 определений. `enemy_factory.gd` проверяет определение, копирует характеристики, задаёт начальное состояние и случайные параметры. `CombatModel.spawn_enemy` проверяет лимиты, выделяет ID, вызывает фабрику и добавляет экземпляр в мир. Фазы босса подключает `Leviathan.setup`.

## Вариант существующего поведения

1. Добавить запись в `EnemyCatalog.DEFINITIONS`, например:

```gdscript
"scout": {"model": "rifleman", "type": "soldier", "hp": 18.0,
    "speed": 3.0, "damage": 4.0, "radius": 0.7, "preferred": 20.0,
    "range": 30.0, "interval": 1.2, "jitter": 0.2},
```

2. Добавить название в `presentation/ui/ui_locale.gd` и EN/RU в `data/localization/ui.json`.
3. Указать появление в `wave_rules.gd` или нужной мировой активности. Сама регистрация не добавляет врага в волны.
4. Запустить `python3 tests/run_all.py --only enemy_factory_test.gd combat_test.gd enemy_ai_test.gd combat_presentation_test.gd`.

Поле `model` выбирает существующую визуальную модель. Рендерер автоматически создаёт пулы моделей из этого же каталога; отдельный список всех врагов больше не нужно поддерживать. Для новой геометрии также нужны запись в каталоге визуальных моделей, файл модели и asset manifest. Тест проверяет существование и предварительную загрузку модели каждого врага.

`type` задаёт общий класс движения: soldier, drone, bike, buggy, keep, garrison, priorityVehicle. Новое специальное поведение требует обработчика в AI. Например, подрывник, дрон-камикадзе и машины поддержки имеют отдельные правила по `kind`; копирование одного флага `detonate` их не переносит.

## Начальное состояние

Необязательная секция `spawn` описывает разброс скорости и части босса. Пример для машины: `"spawn": {"speed_range": [3.4, 4.2]}`. Поля рецепта не попадают в живую запись. Дроны получают начальную высоту, случайное уклонение и его направление по своему `type`.

Для вызова во время игры использовать `model.spawn_enemy(kind, position, options)`, а не прямое добавление в `model.enemies`. `options` сохраняет параметры активностей, например `counts_toward_wave=false`. Прямой `Factory.from_definition` нужен для проверки нового определения вне живого мира; он не регистрирует тип и не обходит лимиты runtime.

## Что сохранено

Сам рефакторинг фабрики сохраняет порядок RNG, лимиты, отдельные ID частей босса и награды. Последующим отдельным изменением включены три машины поддержки: глушитель с волны2, ремонтник и минный заградитель с волны3. Полный список и количество в каждой волне: [enemy-audit-notes.md](enemy-audit-notes.md).
