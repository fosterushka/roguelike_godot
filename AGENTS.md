# Project rules

- Отвечай кратко и понятным языком. Не добавляй emoji и новые bubble-элементы UI без прямого запроса.
- Именованные константы или общий конфиг хранят игровые числа, радиусы, интервалы, скорости и идентификаторы. Не копируй magic literals между системами. Обычные 0/1, индексы и локальные значения геометрии не требуют искусственных обёрток.
- Для общей логики используй переиспользуемые компоненты с одним владельцем. UI читает правила и каталог предметов, а не повторяет игровые формулы.
- Модель предмета, его название и свойства имеют один источник в каталоге. Мир, инвентарь, превью, награды и прогрев используют этот источник.
- Расширяй существующие factories и builders для создания объектов и сборки их частей. Общие свойства передавай через определения/ресурсы; не создавай отдельные копии моделей ради другого места использования.
- Перед новой реализацией найди существующую. Объединяй дубли в затронутой системе, сохраняя уникальное поведение. Избегай глобального рефакторинга вне задачи.
- Не меняй общие Mesh/Material ресурсы ради одного экземпляра: индивидуальные параметры задавай на экземпляре или явно дублируй только изменяемый ресурс.
- Проверяй изменённое поведение подходящими тестами из `tests/run_all.py`; визуальные изменения проверяй реальным рендером. Headless-тест не доказывает внешний вид.
